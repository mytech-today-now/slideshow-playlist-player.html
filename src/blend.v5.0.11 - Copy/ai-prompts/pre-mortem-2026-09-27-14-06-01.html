Issue 01 Core

The analytics library loads before the user grants consent

1. Title

The analytics library loads before the user grants consent

2. Kind

3. Priority

6. Impacted area

Privacy and consent

7. Failure mode

The document includes the Google Analytics loader as an unconditional external script. The application later disables event tracking when consent is absent, but the browser has already requested the vendor script before that application decision can prevent the request.

8. Evidence or rationale

  • index.html:575 includes the analytics script in the static page markup, independently of the consent checkbox.
  • app.js:1537-1561 gates gtag configuration and event tracking after bootstrap, while app.js:9337-9338 reads consent only after the document and modules are being initialized.

Testable assumption: A visitor browser sends the vendor request and network metadata before the in-app consent decision. The unconditional script element supports this expectation, but no browser request was observed because Playwright could not start. Confirm with request interception for consent absent, denied, granted, and blocked by privacy signals; check whether any request leaves before opt-in.

9. Why this matters

A network request to an analytics origin reveals at least the visitor IP address, user agent, and request timing even when application events remain disabled. That conflicts with the user's explicit opt-in control and with the local-first privacy expectation.

10. Recommended mitigation

Remove the unconditional script element. Inject the analytics script only after saved or newly granted consent and only when DNT, Global Privacy Control, and local-file safeguards permit tracking. Keep the current event gate as a second boundary and stop future events immediately after opt-out.

Issue 02 Core

Expired Supabase signed URLs are reused as permanent direct URLs

1. Title

Expired Supabase signed URLs are reused as permanent direct URLs

2. Kind

Core

3. Priority

P1

4. Severity

High

5. Likelihood

Almost certain

6. Impacted area

Private media availability

7. Failure mode

After signing a private object, the application stores the expiring URL in sourceUrl and records signedUrlExpiresAt. On later resolution, remoteUrlForItem returns any HTTP URL immediately, before the stored Supabase reference or expiration timestamp is checked.

8. Evidence or rationale

  • app.js:1114-1119 returns an HTTP sourceUrl as a direct URL.
  • app.js:1158-1166 exits on that direct URL before looking up storageReference.
  • app.js:1176-1183 stores the signed URL and signedUrlExpiresAt on the item.

Testable assumption: A previously signed URL will be rejected by storage after its expiry and cannot be refreshed when treated as a durable direct URL. Confirm with a fake clock and mocked signing endpoint, then assert the resolver refreshes from the stored object reference instead of replaying the expired URL.

9. Why this matters

After the configured signed URL lifetime, a still-authenticated user can keep receiving an expired link and the private item fails instead of being re-signed. The resolver's own signed URL cache expiry cannot help when the app bypasses that resolver.

10. Recommended mitigation

Treat signedUrlExpiresAt as an expiry boundary. Preserve storageReference as the durable value, ignore an expired signed URL, and ask the resolver for a fresh URL when the session can sign it.

7. Failure mode

Confirm using only a synthetic session; inspect whether the key and token fields can be read, and never print or copy a real token.

The token grants access to private media until it expires or is revoked. Browser LocalStorage is readable by same-origin JavaScript and is not an encrypted secret store. This is a client-side threat boundary, not evidence that the checkout currently contains a script injection.

10. Recommended mitigation

Reduce credential persistence by default. Prefer an in-memory or tab-scoped session unless the user explicitly chooses persistence, and explain that same-origin scripts can read a persisted token. Never claim client-side encryption prevents active same-origin script access.
