Failure mode

Directory scans build path hints from the selected root's display name and relative descendants. Library deduplication then compares normalized relative path strings, while rememberDirectoryHandle reuses a saved handle when only its name matches. Two different roots called Assets with a file at the same relative path can therefore receive the same path hint and directory ID. If size also matches, addHandles can report the second file as existing and retain the first file's bytes.

Evidence status: High. The name-only root matching and path comparison are directly visible. The exact user impact is reproducible with the proposed synthetic fixture.

Evidence or rationale

  • app.js:4573-4580 remembers a directory handle by comparing handle.name only.
  • app.js:4582-4604 seeds each path hint from dirHandle.name and appends relative child names.
  • app.js:4711-4729 calls hasSameLibraryMediaIdentity and uses size as a secondary compatibility check.
  • media-relink.js:1-17 normalizes paths to lowercase and stableLibraryPath accepts only relative path plus name.
  • tests/e2e/file-picker-identity.e2e.spec.mjs covers same-name files and distinct child folders, but not two separate roots with identical root and relative names.

A same-size media collision is silent: the UI can say an item is already present even though the user selected different content. The second root handle may also be represented by the first saved handle, so later relinking can search the wrong directory. Lowercasing paths can add collisions on case-sensitive file systems. This is data integrity risk in the central local-media import path.
